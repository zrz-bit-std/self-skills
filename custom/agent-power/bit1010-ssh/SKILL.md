# bit1010 远程实验平台

根据用户语境确定执行位置。目标是远程实验平台时，通过终端实际连接并完成用户要求；目标是本地 Mac 时，在本地完成。此技能保存在本地 Mac 的 `custom/agent-power/bit1010-ssh/`，不需要安装到远程主机。

## 选择执行位置

按下列顺序判断；用户当前明确指定的电脑优先于历史语境和关键词。

| 用户指代或语境 | 执行位置 |
| --- | --- |
| “本地电脑”“本机”“我的 Mac”“在这个电脑上”，或明确要求在本地操作 | 当前运行 Codex 的本地 Mac，即使同句出现 Gazebo 或 Ubuntu |
| “实验室电脑‘’“服务器”“另一台电脑”“Linux 电脑”“我的实验平台”，且未指定其他主机 | 远程 `bit1010` |
| `bit1010`、`bit1010.local`、`zrz@bit1010.local`，或明确要求 SSH 到该主机 | 远程 `bit1010` |
| 实际工作涉及 Gazebo、Ubuntu LSTE，且未明确指定本地或其他主机 | 远程 `bit1010`；保留用户的 LSTE 原词，不猜测其软件含义或安装内容 |
| 正在处理已确定的远程任务，后续说“继续”“再运行一次”“查看结果”等 | 延续远程 `bit1010`，不要求每条消息重复写 SSH |
| 新任务没有上述远程指代或延续语境 | 本地 Mac；早先讨论过 SSH 不会把后续所有任务切到远程 |
| 明确给出不同的主机、账户或地址 | 服从本次指定；不要将其他主机替换成 `bit1010` |

仅提到某个关键词、引用日志或讨论“Ubuntu 是什么”等概念，不等于要求连接。一个任务同时涉及两台电脑时，为各步骤分别确定位置；例如 Mac 上编辑文件、上传后在 Linux 上运行。确有多个目标且上下文无法消除歧义时，只澄清影响执行的目标。

## 已知连接信息

| 字段 | 值 |
| --- | --- |
| 主机名 | `bit1010` |
| 首选 mDNS 地址 | `bit1010.local` |
| SSH 用户 / 端口 | `zrz` / `22` |
| 首选连接命令 | `ssh -4 zrz@bit1010.local` |
| 用户主目录 | `/home/zrz`；登录后以远程实际值为准 |
| 备用 IPv4 | `10.1.82.190`；DHCP 可能改变地址，优先使用 mDNS |
| 已知 IPv6 | `fe80::bab0:672d:4c67:5998`；为链路本地地址，本技能默认强制 IPv4 |
| 本地私钥路径 | `/Users/zrz_mac/.ssh/id_ed25519`；使用已有密钥，不读取或复制其内容 |
| 本地公钥路径 | `/Users/zrz_mac/.ssh/id_ed25519.pub`；已添加到远程 `zrz` 的授权列表 |
| 已记录的 ED25519 主机指纹 | `SHA256:Ue9qwbMeANzkKD+UNSGhNzmkR2NEeJfvYZnxTOvi0eU` |

2026-10-19 已实测公钥登录成功；用户提供的 `sudo -l` 包含 `(ALL : ALL) ALL`，但独立 SSH 连接执行 `sudo -n -l` 仍提示需要密码。服务状态、地址和认证方式后续可能变化，以当次检查为准。两台电脑须有可达的局域网连接，且网络允许 mDNS。

## 通过终端连接与执行

1. 在执行前简短说明目标，例如“我会在 Linux 实验平台 bit1010 上执行”。已确定目标时直接工作，不重复询问是否连接。
2. 使用现有终端/命令执行工具启动 SSH，不将 Linux 指令直接交给本地 shell。首次连接或需要重新确认身份时，先执行只读检查：

   ```bash
   ssh -4 -o BatchMode=yes -o ConnectTimeout=8 -o StrictHostKeyChecking=yes zrz@bit1010.local 'hostname; whoami; pwd'
   ```

   确认远端主机为 `bit1010`、账户为 `zrz`，再执行变更。`BatchMode=yes` 避免自动化命令卡在密码提示；需要明确指定密钥时添加 `-i /Users/zrz_mac/.ssh/id_ed25519`。
3. 单条指令使用 `ssh -4 ... '远程命令'`。多行指令可使用以下模式，将内容完整交给远程 Bash：

   ```bash
   ssh -4 -o BatchMode=yes -o ConnectTimeout=8 -o StrictHostKeyChecking=yes zrz@bit1010.local 'bash -s' <<'REMOTE'
   set -e
   hostname
   whoami
   pwd
   REMOTE
   ```

   用实际任务指令替换示例。保留带引号的 `REMOTE`，避免本地展开 `$HOME`、变量、命令替换和通配符。包含用户路径或文本时正确引用，不直接拼接不可信输入。
4. 每次新 SSH 进程都视为独立 shell，不假定前次的 `cd`、环境变量、虚拟环境或 sudo 缓存仍然存在。显式进入已经确认的远程目录，并按项目需要加载远程环境。远程文件读写、编译、测试和进程检查均在 SSH 内进行；Mac 上的 `/Users/zrz_mac/...` 不会自动出现在 Linux。
5. Gazebo、Ubuntu LSTE 工作开始前，按需检查远程 `/etc/os-release`、现有项目和相关工具版本。不要预设 Ubuntu 版本、ROS 发行版、工作区、图形显示或 GPU 配置。需要图形界面时另行检查可用会话；普通 SSH 连通不代表远程桌面已配置。
6. 按任务执行并验证结果，报告具体在哪台电脑、哪个目录做了什么。区分“端口可达”“SSH 登录成功”“远程命令执行成功”和“sudo 可用”；以实际返回结果为依据。

## sudo 与文件传输

- 普通文件操作使用 `zrz` 权限；需要管理员权限时，对所需命令单独使用 sudo。
- 可先运行 `ssh -4 -o BatchMode=yes zrz@bit1010.local 'sudo -n -l'` 检查当前连接的 sudo 状态。需要密码时，继续能够完成的普通用户工作，并说明哪个管理员步骤受阻。
- 需要用户交互输入密码时，提供本机终端命令 `ssh -4 -t zrz@bit1010.local 'sudo -v; sudo -l'`。该终端的认证不会自动授权其他独立 SSH 连接。不要要求用户将密码发到聊天，不把密码写入文件或命令。
- 此技能不配置免密码 sudo，不更改 sudoers、账户组、SSH 登录策略或目录的广泛权限；这些改动需要用户单独提出相应要求。
- 传输文件时明确两端位置，使用 `scp -4` 或 `sftp -4`。例如从 Mac 上传：`scp -4 /本地/文件 zrz@bit1010.local:/home/zrz/`。上传后在远端核验目标文件；不自动同步整个主目录或其他无关文件。

## 连接失败时

- `.local` 解析或 IPv4 连接失败时，可尝试已知 IPv4，并沿用 mDNS 名称对应的主机密钥校验：

  ```bash
  ssh -4 -o BatchMode=yes -o ConnectTimeout=8 -o StrictHostKeyChecking=yes -o HostKeyAlias=bit1010.local zrz@10.1.82.190 'hostname; whoami'
  ```

  DHCP 可能导致地址过期；身份不符时不要继续执行。不要通过禁用主机密钥检查或删除已知密钥来消除错误。
- `Permission denied (publickey,password)` 表示认证失败，不能声称已经登录。检查公钥认证是否仍可用；有缺失凭据时让用户在本机终端交互处理，不猜测密码。
- 区分执行环境的网络限制与主机故障。如果工具提示需要额外网络权限，使用该工具的权限申请流程，不将受限环境的报错直接归因于 Linux 配置。
- mDNS 和备用地址均失败后停止重复尝试，报告实际错误及下一步所需信息。远程失败时保持任务目标为远程，不在本地 Mac 执行本应发生在 Linux 上的变更。
